# SFT：示范答案怎样变成模型的学习信号

假设一个已经通过大量文本学会预测后续 token 的预训练语言模型，看到“想借相机七天，帮我填申请”，直接写出一份表格，把用户没有提供的开始日期填成今天。它能续写文字，并不表示它已经学会设备申请应怎样办理。提示词可以要求它先澄清，但若希望模型在一类任务上更稳定地遵循“缺参先问、信息齐全后再整理”的行为，可以准备相应示范，让这种回答方式参与参数训练。

监督微调（Supervised Fine-Tuning，SFT）从已有模型出发，用输入和期望输出构成的训练样本，调整模型在这些条件下生成目标回答的概率。它改变的是模型参数及行为倾向，不会直接把数据库连接或工具权限装进模型，也不能仅凭一条示范保证今后不再填错日期。

先修 [Transformer](#/lesson/transformer-basics) 已解释 token、因果注意力和下一个 token 预测。本篇沿一段假设设备借用对话，解释样本怎样进入模型、哪些位置产生损失，以及损失如何推动学习。所有对话、token 划分和概率都是教学设定，没有训练或运行实际模型。

## 预训练与 SFT 可以使用相同的预测形式

在常见的自回归预训练中，模型阅读大量文本，根据前面的 token 预测下一个 token，学习语言规律、知识关联与多种文本结构。SFT 可以继续使用同样的下一个 token 预测目标，但数据选择与监督位置变了：训练材料被组织成期望完成的任务，目标回答表达希望模型采取的行为。

因此，区别不能简化成“预训练不用标签，SFT 才有标签”。预训练也有预测目标，只是通常由原始文本中的后续 token 提供；SFT 的示范经过选择或编写，决定哪种响应值得模仿。一个训练阶段也不会因为名字叫 SFT 就天然拥有高质量监督，错误示范同样会成为学习信号。

InstructGPT 论文描述了先收集标注者编写的理想行为示范，对 GPT-3 做监督微调，再进行其他阶段。论文中的完整结果不能全部归因于 SFT，因为后续训练还改变了模型。本篇只讨论示范到监督损失这一段。[Ouyang 等：Training language models to follow instructions with human feedback](https://arxiv.org/abs/2203.02155)

把最新借用期限写进许多训练答案，也不等于建立了实时政策服务。SFT 更适合学习怎样利用提供的政策、怎样澄清和怎样表达不确定；经常变化的事实仍要在推理时从当前资料或工具取得。模型能记住某个数字，并不能证明它知道数字何时失效。

## 多轮对话里，哪些位置是学习目标

本例希望学会的行为是先补日期，再整理草稿。一个完整示范如下，日期仅为假设：

| 角色与轮次 | 消息内容 | 本例是否计算目标损失 |
| --- | --- | --- |
| system | 你是设备借用助手。信息不足时先澄清，不替用户补日期。 | 否，作为上下文 |
| user 1 | 想借 CAM-18 七天，帮我填申请。 | 否，作为上下文 |
| assistant 1 | 请提供借用开始日期。 | 是，学习澄清行为 |
| user 2 | 10 月 8 日开始，10 月 14 日归还。 | 否，作为上下文 |
| assistant 2 | 草稿：CAM-18，10 月 8 日至 10 月 14 日，尚未提交。 | 是，学习忠实整理与状态表达 |

消息不能只把中文拼接起来就结束。训练时要用与模型匹配的对话模板（chat template），将角色、轮次边界和结束标记转成模型认识的序列，再由 tokenizer 编码。模板错误可能让模型分不清谁在说话，甚至让“请提供日期”被当成用户输入而非助手示范。

这里选择对两个 assistant 回复都计算损失，而 system 与 user 位置不直接计分。这称为只监督助手消息的一种策略；也可以只监督最后一轮，或者对完整文本计算损失，取决于数据与训练目标。只训练最后一轮，会减少这条样本对第一轮澄清行为的直接监督，所以“有多轮数据”和“每个助手轮次都参与训练”不是一回事。表格描述正文的监督意图，角色标记、回复结束符等特殊 token 是否计分，还要核对模板实际产生的 mask。

TRL 的 SFT Trainer 支持会话数据与 prompt-completion 数据，并提供 assistant_only_loss 和 completion_only_loss 等配置。前者需要模板能标出助手生成区间，后者按 prompt 与 completion 的数据边界决定训练范围。它们不是名字不同的同一个开关；实际训练前应读回 token 与 mask，而不是只查看原始 JSON。[TRL：SFT Trainer，2026-09-28 查阅](https://huggingface.co/docs/trl/sft_trainer)

## Teacher forcing 为什么不会让模型偷看答案

教师强制（teacher forcing）指训练预测某个目标 token 时，前缀使用样本中正确的历史 token，而不是先让模型自由生成前文再拿它的结果往下算。例如预测第二个助手回复中的“归还日期”时，输入包含示范里的用户日期和已经出现的正确回答前缀。

这样可以把整段训练序列一次送入 Transformer，并行计算多个位置的预测。因果注意力遮罩（causal attention mask）保证一个预测位置只能利用此前的 token，看不到要预测的当前目标和未来答案。模型训练的仍是“给定前文，预测后文”，而不是把答案放在可见位置再抄一次。

实现时还要对齐一位偏移：位置 $t-1$ 的预测分布对应真实 token $z_t$。不少因果语言模型在内部处理 logits 与 labels 的移位，调用方若再手工错移一次，训练就会对不上。理解偏移关系比记住某个库要求“左移还是右移”更可靠，尤其当数据整理器与模型各自处理一部分时。

推理时没有完整示范答案可以提供。模型生成第一步以后，后续前缀包含它自己的输出；早期出错可能改变后续输入。这说明训练时损失下降，不自动等于自由生成时任务成功。验证仍要让模型实际完成澄清与草稿任务，检查是否在缺参时停下来，以及是否保持用户原始字段。

## 标签遮罩如何进入交叉熵

标签遮罩（label mask）决定哪些目标 token 计入损失。它和因果注意力遮罩承担不同工作：前者控制计分，后者控制可见信息。用户消息可以不计分，却仍是助手生成所依赖的上下文；将其 label 设成忽略值，不等于把用户文字从输入中删除。

设序列为 $z_1,\ldots,z_T$，$T$ 是 token 总数，$m_t$ 表示第 $t$ 个目标是否参与训练，参与时为 1，否则为 0。用参与位置的平均交叉熵表示本例目标：

$$
\mathcal{L}(\theta)=-\frac{1}{M}\sum_{t=1}^{T}m_t\log p_\theta(z_t\mid z_{<t}),\qquad M=\sum_{t=1}^{T}m_t
$$

$\theta$ 是可训练参数，$p_\theta$ 是模型给真实目标 token 的概率，$z_{<t}$ 是此前 token。这里使用自然对数，$M$ 是有效目标数，必须大于零。符号写成平均值是为了明确归一化；实际训练在批次与梯度累积之间如何求和或平均，要核对实现，不能随意更换分母。

交叉熵（cross-entropy）在目标是单个正确 token 时，等于该 token 的负对数概率。假设从示范中取出三个参与监督的示意 token，它们的目标概率分别为 0.5、0.25、0.8。这里只用三个符号位置说明计算，不声称中文短句恰好由三个 token 组成。损失为：

$$
\mathcal{L}=-\frac{\log 0.5+\log 0.25+\log 0.8}{3}=\frac{\log 10}{3}\approx0.7675
$$

第二个位置的目标概率最小，负对数项约为 1.3863，对总损失贡献最大。训练通过反向传播计算参数梯度，优化器据此更新参数，使这类正确目标在相应上下文中的概率有机会提高；一次更新也会影响其他输入，不能理解成给某一条答案单独写入一条规则。

很多训练实现使用 -100 作为忽略标签的标识，padding 和不监督的位置不会进入交叉熵。它不是一个应当预测出来的词表 token。TRL 文档说明了逐 token 交叉熵、移位与忽略位置。[TRL：Computing the loss 与 Label shifting and masking](https://huggingface.co/docs/trl/sft_trainer#looking-deeper-into-the-sft-method)

假设本段另有两个用户 token，其概率为 0.9 和 0.1，但 mask 都为 0，它们既不加入分子，也不加入有效目标数 3。若错误地除以全部五个 token，会得到约 0.4605，看起来损失更低，实际只是分母变了。评估训练日志前，必须知道计分的是哪些位置。

## 数据配比与切分决定模型在学什么

如果训练集中几乎每条输入都信息齐全，模型很少看到“应该先问”的示范，即使单条澄清样本写得很好，也可能继续倾向于直接交付。反过来，澄清样本过多又可能让完整请求反复被追问。要让任务分布包含真实会遇到的完整输入、缺参、修改、无法确定和成功结束，而不是只收集漂亮的最终答案。

多轮样本还要防止未来信息泄漏。训练 assistant 1 时，它只能看到第一轮用户消息，不能把 user 2 的日期提前合并进第一轮上下文。否则模型学习到的是“已经知道日期时怎么提问”，而不是实际产品中缺日期的判断。因果 mask 能限制序列位置，但如果数据预处理把未来答案搬到了前缀里，它无法知道那是泄漏。

数据集之间也要分离。同一个任务的不同措辞、同一对话拆出的多个片段，不宜随机散落到训练集和测试集，让测试只是认出近似样本。可以按原始任务、文档家族或时间分组，再根据目标设计未见情形。InstructGPT 的评估中使用了训练数据未出现客户的提示，这说明作者也明确区分了训练来源与评估来源；它并非所有业务都应照搬的唯一切分法。[InstructGPT：评估分布说明](https://arxiv.org/abs/2203.02155)

训练损失持续下降，验证任务却停滞或退步，可能是在记忆训练样本、过度偏向某种表达，或削弱已有能力。过拟合（overfitting）不能仅凭一个训练曲线判断，应同时观察保留集损失与真实任务指标，例如正确澄清率、字段忠实度、额外追问和无依据填充。模板、mask、数据比例与学习率都有可能影响结果，不应一见问题就只增加训练轮数。

## LoRA 回答的是更新哪些参数

SFT 描述监督信号与训练任务，低秩适配（Low-Rank Adaptation，LoRA）描述一种参数更新方式。全量微调可以让原模型许多参数参与更新；LoRA 通常冻结原有权重，在选定层加入可训练的低秩更新矩阵。两者都可以用前面的示范与交叉熵进行 SFT。[Hu 等：LoRA，摘要中的方法定义](https://arxiv.org/abs/2106.09685)

因此，“用 LoRA 训练过”还没有说明训练目标是什么，也没有说明哪些消息被监督。反过来，“做了 SFT”也没有说明更新的是全模型、LoRA 参数还是其他参数子集。TRL 文档把 PEFT adapters 作为 SFT Trainer 的一种集成选项，正体现了这两个维度可以组合。本文没有据此声称某个配置已运行，或 LoRA 在这个任务上必然优于全量更新。

后续若要用回答之间的比较来改变模型偏好，训练信号会与直接模仿示范不同，见 [RLHF](#/lesson/rlhf)。在进入那里以前，应先能检查一条 SFT 样本的角色边界、可见前缀、有效标签与损失分母；这些基础若错了，换一种优化方法也不能自动修复数据含义。

**一分钟回答：** SFT 从已有模型出发，用输入与期望回答的示范继续训练。对自回归模型，通常用 teacher forcing，在正确历史前缀下预测下一个 token，计算交叉熵并更新参数。因果注意力防止看未来，label mask 决定哪些位置计分，用户消息不计分仍可以作为上下文。多轮数据可以监督全部助手回复，也可以只监督最后一轮，要核对模板和实际 mask。SFT 学到的是数据分布中的行为倾向，不能保证事实实时或任务必然成功。LoRA 只是可选的参数更新方式，不是 SFT 的同义词。

**追问一：答案已经拼进输入，为什么不是作弊？** 因果模型用前一位置预测下一 token，并遮住未来。teacher forcing 提供正确历史，当前目标在预测时不可见。但数据整理若把后续信息复制到前面的提示里，仍会造成泄漏，attention mask 无法修复这种语义错误。

**追问二：把用户 label 设为 -100，模型是不是不再看用户问题？** 不是。label mask 让这些位置不直接贡献损失，输入与注意力可见性由其他机制处理。助手目标的预测仍依赖用户文字，梯度也可能通过这些上下文表示影响可训练参数。

**追问三：训练 loss 很低为什么仍不会澄清？** 可能测试请求超出训练分布，澄清样本过少，模板或 mask 没有监督到第一轮回复，也可能只是在 teacher forcing 条件下预测得好。应检查实际训练标签，再用自由生成任务评估，而不是仅增加 epoch。

有效目标数变为 2，新损失为 $-(\log0.5+\log0.8)/2=-\log0.4/2\approx0.4581$。概率没有变化，模型没有更新，只是移除了原来较难的监督位置，因此不能把下降当成能力提升。

# 强化学习：一次成功怎样改变下一次选择

假设订单助手知道怎样调用查询工具，却有时仍根据昨天的聊天记录回答当前状态。一次任务成功，只说明这次做对了；把“下次记得查询”写进提示，可能改善同一会话，但模型参数没有因此改变。要让大量成功与失败经验影响生成策略，需要明确哪些行为得到奖励，再通过训练更新策略。这是强化学习（Reinforcement Learning，RL）关心的问题。

本课承接 [RLHF](#/lesson/rlhf) 和 [Agent 评估](#/lesson/agent-metrics)，从一轮任务走到回报、优势与策略更新，再解释 PPO 和 GRPO 的核心差别。示例中的订单、轨迹、奖励与概率都为教学假设，不是实际训练结果。这里只展示算法接口与关键计算，不一次推完全部优化过程。

## 把一次 Agent 任务写成与环境的交互

一个回合（episode）从指定起始条件开始，到成功、失败或预算耗尽结束。状态（state）描述作出决定时的环境情况；动作（action）是 Agent 选择的行为；环境执行后返回观察与奖励，并进入下一状态。策略（policy）给出在某种状态下选择各动作的概率，常记为 $\pi_\theta(a\mid s)$，其中 $\theta$ 是待训练参数。

对语言 Agent，可以在应用层把“查询订单”“提交回答”视为动作，状态包含问题、可用工具和已观察结果。但模型往往只能看到部分环境：它并不知道数据库里尚未查询的值。因此工程上提供的历史记录只是状态信息的表示，不能假设它等于完整世界。描述算法时用 $s_t$ 表示第 $t$ 步决策输入，真实任务还需处理观察不完整和状态过期。

在 token 层训练语言模型时，动作通常是下一个生成 token，决策输入是问题与已生成前缀；一个工具调用由若干 token 组成。应用层的一步与训练层的一步粒度不同。本课先用完整工具行为解释任务，再指出怎样把反馈分配给生成过程，避免把一个业务 API 调用误认为 PPO 固定规定的动作单位。

奖励（reward）是训练环境给出的评价信号，不等于用户满意度或事实本身。例如测试环境可以规定：查对订单、按当前结果回答、没有执行未请求的写操作，三项都满足时奖励 1，否则为 0。这个定义可以由程序与人工审核共同验证；如果只奖励答案里出现“已查询”，策略可能学会说这句话而不真正查询。

## 一步奖励与整段回报有什么区别

奖励可以在中间步骤出现，也可以只在回合末尾给出。回报（return）把从当前步骤起的后续奖励合起来，常用折扣系数控制远期奖励的权重：

$$
G_t=\sum_{k=0}^{T-t-1}\gamma^k r_{t+k}
$$

$G_t$ 是从第 $t$ 步开始的回报；$T$ 是总步数；$r_{t+k}$ 是对应一步的奖励；$\gamma$ 是折扣系数，常取 0 到 1。这里约定动作完成后得到该步奖励，所有索引都按这一定义使用。若三步奖励依次为 $[0,0,1]$，且 $\gamma=0.9$，则 $G_0=0.81$、$G_1=0.9$、$G_2=1$。

如果有限任务采用 $\gamma=1$，三个时刻的回报都是 1。折扣不是越小越好：过度偏向眼前收益，可能让策略不愿意进行稍后才能有用的查询。任务长度、奖励时机和目标决定怎样设置，不能把一个默认值直接套到所有 Agent 上。

最终成功也没有自动告诉我们哪一步值得奖励。先查询正确数据、再偶然猜中结论，与全程依赖真实证据都可能得到同一个末尾分数。如何把整体结果归因到前面的行为，叫信用分配（credit assignment）。末尾奖励简单，但对长任务指导较粗；每一步都评分更细，却需要可信的过程标准，还可能错误奖励形式上漂亮的过程。

## Advantage 问的是“比基线好多少”

只看奖励大小，会把难题上的一次成功与简单任务上的普通表现混在一起。优势（advantage）把某个行为的结果与基线比较。常见写法是 $A_t=Q(s_t,a_t)-V(s_t)$：$Q$ 表示当前状态选择这个动作后预期得到的回报，$V$ 表示按当前策略在该状态下通常能得到的回报。它们是真实期望概念，训练中需要估计。

正优势表示这个行为比基线好，负优势表示比基线差。策略梯度利用这种相对信号调整动作概率，而不是把所有得到正奖励的动作都同样增加。PPO 常采用 actor-critic 结构：actor 是策略，critic 或价值模型估计状态价值，为优势估计提供基线。价值模型预测未来回报，奖励模型评价输出，它们不是同一个职责。

SFT 与 RL 的监督形式也不同。SFT 对示范中的目标 token 增加似然，训练信号来自已有示范；RL 从策略采样的行为和反馈中估计哪些选择值得提高概率。SFT 可以提供良好起点，RL 进一步利用结果信号，二者可以接续。若奖励标准有漏洞，RL 会优化漏洞；它不会天然比示范学习更接近真正业务目标。

## PPO 为什么比较新旧动作概率

近端策略优化（Proximal Policy Optimization，PPO）交替采样与优化，并希望避免用一批数据把策略改得过猛。原论文给出 PPO-Clip 的概率比值与裁剪目标。[PPO 论文：第 2—3 节](https://arxiv.org/abs/1707.06347)

先定义同一状态动作在当前策略与采样旧策略下的概率比值：

$$
\rho_t(\theta)=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{old}(a_t\mid s_t)}
$$

$\pi_{old}$ 是生成这批样本的旧策略，更新过程中固定；$\rho_t=1$ 表示概率尚未改变。这里用 $\rho$ 表示比值，避免与奖励 $r$ 混淆。PPO-Clip 最大化的核心项为：

$$
L_{clip}=\mathbb{E}_t\left[\min\left(\rho_t A_t,\operatorname{clip}(\rho_t,1-\delta,1+\delta)A_t\right)\right]
$$

$\delta$ 是裁剪宽度，$\operatorname{clip}$ 把比值截在指定区间内，$\mathbb{E}_t$ 表示对采样步骤取平均。取两项较小值，是为了不让某个样本因概率朝有利方向变化过多而继续提供同样的优化激励。

例如 $A_t=1$，旧概率 0.2、新概率 0.3，得到 $\rho_t=1.5$。若 $\delta=0.2$，未裁剪项为 1.5，裁剪项为 1.2，采用 1.2。继续提高这个动作概率，不会继续增加该样本这一项的收益。若 $A_t=-1$、比值为 0.5，未裁剪项为 -0.5，裁剪项为 -0.8，采用 -0.8，限制过度降低坏动作概率带来的激励。

这并不等于强制所有概率比值永远在 0.8—1.2 内。裁剪发生在目标函数里，参数共享和其他样本仍会影响最终分布，实际实现还可能监测 KL 并提前停止。OpenAI 的 Spinning Up 说明也明确指出，裁剪不能绝对保证新策略不偏离过远。[Spinning Up：PPO-Clip 解释](https://spinningup.openai.com/en/latest/algorithms/ppo.html)

这里比较的旧策略，与 RLHF 中用于约束长期漂移的参考策略也要区分。前者对应当前采样批次；后者可能保持在较早的 SFT 起点。两者都与“不要改太远”有关，但角色和更新时机不相同。

## GRPO 怎样用一组结果代替价值基线

DeepSeekMath 提出的组相对策略优化（Group Relative Policy Optimization，GRPO）保留了类似 PPO 的裁剪策略目标，但利用同一个问题下多个输出的奖励计算相对优势，从而不需要额外训练该设置中的价值模型。原论文还使用参考策略 KL 项；不能把 GRPO 简化成“只把奖励减个均值”。[DeepSeekMath：第 4.1 节](https://arxiv.org/abs/2402.03300)

现在固定一个训练问题：“查询订单 O-18 当前状态；只需解释，不执行取消。”测试后端状态为已发货。旧策略从同一起点采样四条轨迹：

| 轨迹 | 行为与最终输出 | 末尾奖励 |
| --- | --- | ---: |
| 1 | 查询 O-18，依据返回回答已发货，没有写操作 | 1 |
| 2 | 没查询，依据旧聊天回答待发货 | 0 |
| 3 | 查询错误订单，给出不匹配的状态 | 0 |
| 4 | 查询 O-18，换一种正确措辞回答已发货，没有写操作 | 1 |

这是人工构造的四次采样结果，用来演示结果监督；不是对真实工具或模型的测评。奖励数组为 $[1,0,0,1]$，组均值为 $\bar r=0.5$。采用除以组大小的总体标准差，则 $s=\sqrt{(0.25+0.25+0.25+0.25)/4}=0.5$。归一化优势写成：

$$
A_i=\frac{r_i-\bar r}{s+\epsilon}
$$

$i$ 表示组内第几条输出。为展示精确手算，暂取 $\epsilon=0$，得到 $[1,-1,-1,1]$。数值实现常加入一个小的正数避免零分母；若这里取 $\epsilon=10^{-8}$，得到约 $[0.99999998,-0.99999998,-0.99999998,0.99999998]$，显示时才近似写成正负 1。这个 epsilon 是本课明确加入的稳定项，原论文结果监督公式直接除以 std；也不要把它与前面的裁剪宽度 $\delta$ 混为一个参数。

原论文的结果监督设置将同一输出的归一化奖励赋给该输出各 token 的优势。它鼓励成功输出中的采样选择、压低相对失败输出的选择，但并没有精确证明轨迹中每个 token 都是成功原因。轨迹 1 与 4 的奖励相同，也不表示它们在耗时、成本或措辞上同样好；当前奖励定义没有区分这些目标。

若同组全得 0，或同组全得 1，标准差都是零。加入稳定项后相对优势均为零，这组没有提供区分输出好坏的组内信号；不代表模型完美，也不代表其他目标项完全没有梯度。GRPO 减少了价值模型开销，却需要为同一问题采样一组输出，也依赖组内差异、奖励质量与训练资源，不能断言它总比 PPO 便宜或有效。

## 从交互记录到权重更新，还需要训练系统

一个完整训练批次包含任务采样、受控环境执行、奖励计算、优势估计、策略更新，以及独立评估。所谓在线 RL，通常指训练数据随当前或近期策略的交互产生；不等于把未经验证的新权重直接放给生产用户。订单例子应在可重置的测试环境中执行，确保四次采样不会互相污染或真实修改用户数据。

仅把失败总结放进记忆、让 Agent 再试一次，改变的是下一次输入。除非实际执行梯度训练或其他参数学习，它不属于本课意义上的策略权重更新。反过来，拿历史日志训练，也需要检查日志来自什么策略、奖励能否重建，不能把任意成功对话直接称作 PPO 训练数据。

训练奖励上涨以后，仍需用未见任务检查真实成功率、必要工具调用、权限约束、成本和分布变化。可验证奖励也可能漏掉隐藏要求，学习过程可能过度适应测试规则。PPO 的裁剪和 GRPO 的相对基线都不会自动修复错误环境或错误验收标准。

<summary>面试怎么回答</summary>

**一分钟回答：Agent 强化学习怎样从一次成功中学习？**

把任务组织成回合，策略根据状态或观察历史选择动作，环境返回奖励。回报汇总后续奖励，优势比较某个选择与基线的好坏，再用于更新策略参数。PPO 用新旧动作概率比值和裁剪目标限制过强的更新激励；GRPO 在同一问题下采样一组输出，用组内奖励计算优势，避免额外价值模型。二者都依赖奖励与环境质量。记忆里写一条反思只改变上下文，不能自动等同于权重训练。

**追问一：reward、return、advantage 有什么区别？**

Reward 是某一步得到的评价，return 汇总从当前开始的后续评价，advantage 再减去或比较基线，表示相对表现。最终奖励相同的两条轨迹，不一定每一步都同样好，信用分配仍是难点。

**追问二：PPO clip 是否保证概率不超过边界？**

不保证。它裁剪的是目标中的一项，用于去掉过度改变的激励，不是对模型输出分布施加硬约束。参数共享和其他项仍可推动变化，所以还要监测更新幅度和实际表现。

**追问三：GRPO 一组全失败怎么办？**

这一组缺少奖励差异，归一化后没有相对优势信号。应检查问题难度、采样覆盖和奖励是否过于稀疏，再决定数据与训练调整。不能靠给分母加 epsilon 就凭空得到有意义的学习方向。

## 练习：把计算和结论分开

另一个问题的四条输出奖励都是 1。使用本课的总体标准差和正 epsilon，优势是多少？这能否证明模型已经学会任务？再考虑一个正优势样本，旧动作概率 0.2，新概率 0.24，裁剪宽度为 0.2，它的比值和核心目标项是多少？

<summary>参考思路</summary>

全为 1 时均值为 1、标准差为 0，分子均为零，所以四个优势都是零。这只说明本组无法区分，不能证明未见问题也成功，或所有必要条件都被奖励覆盖。

正优势取 1 时，概率比值为 $0.24/0.2=1.2$，未裁剪与裁剪项都为 1.2，核心项也是 1.2。若新概率继续上升，该样本的正优势项进入平台区；这仍不是对实际新概率的硬上限。

# 强化学习入门：状态、奖励、回报与优势

假设一个订单 Agent 收到“查询 O-18 当前状态，只解释，不取消”的请求。它会调用查询工具，却也可能凭昨天的聊天记录回答。把“下次先查询”写进反思，可以改变后续对话的输入；这条反思本身不会修改模型参数。**强化学习（Reinforcement Learning，RL）**讨论的是另一种学习：让策略在环境中尝试动作，依据得到的反馈调整参数，使以后更倾向于有利的选择。

这里的**策略（policy）**是作决定的规则。对可训练模型，它可以表示为 $\pi_\theta(a\mid o)$：给定当前观察 $o$，参数 $\theta$ 决定动作 $a$ 的概率。本篇只解释一轮交互怎样产生学习信号，以及最基本的参数更新方向。订单、环境、分数和概率均为教学假设，没有实际训练 Agent。已有示范怎样训练模型可先看 [SFT](#/lesson/sft)；人类偏好怎样提供反馈见 [RLHF](#/lesson/rlhf)。

## 一次任务怎样成为一个 episode

**回合（episode）**从任务开始，到回答完成、失败或预算耗尽时结束。环境的**状态（state）**包含真实情况，例如数据库中 O-18 已发货、用户没有授权取消。Agent 获得的**观察（observation）**只包含当前输入、可用工具和已经返回的结果；查询前它看不到数据库里的最新状态。因此，不能把对话历史当作完整状态，也不能把旧聊天中的“待发货”当作当前事实。[OpenAI Spinning Up 的 RL 概念说明](https://spinningup.openai.com/en/latest/spinningup/rl_intro.html)区分了完整状态与可能遗漏信息的观察。

在这个假设的测试环境里，一轮成功轨迹可以这样走完：

1. 初始观察是用户请求、订单号 O-18 和“只解释”的权限边界。Agent 的动作是调用只读查询工具，指定 O-18。
2. 环境返回“已发货”。Agent 把这条工具结果加入下一步观察，动作是拟出“查询结果显示已发货”的候选答复，不调用取消工具。
3. Agent 提交答复并停止。测试器核对订单号、答案与工具结果是否一致，以及有无越权写操作；合格时给这一步的末尾奖励 1，回合结束。

失败轨迹可能跳过第一步，直接按旧聊天回答“待发货”。若验收要求当前工具证据，这条轨迹得 0。**动作（action）**在上面的应用视角是“查询”或“回答”；若直接训练语言模型，单个动作通常是生成下一个 token，一个工具调用由多个 token 构成。两种粒度不能直接混用。模型也没有天然的数据库权限：环境须控制工具、权限与可重置的测试数据。

**奖励（reward）**是环境按照规则给出的评价，不是事实真相或用户满意度本身。这里的 1 需要同时满足“查对订单、按当前结果回答、没有未授权写操作”；只检查答复中有没有“已查询”三个字，会鼓励说出这三个字，却不能保证真实查询。规则若漏掉耗时或成本，两条同分轨迹在这些方面仍可能不同。奖励的定义决定策略会被引向什么行为，不能把训练分数上涨直接当成业务目标达成。[Spinning Up 的奖励与回报定义](https://spinningup.openai.com/en/latest/spinningup/rl_intro.html#reward-and-return)也把奖励函数放在具体环境中定义。

## 一步奖励怎样变成后续回报

若环境只在末尾给分，前面的查询动作当时可能得到 0，却对最终成功很关键。**回报（return）**把从当前步骤起的后续奖励合起来。沿用“动作完成后得到该步奖励”的索引约定，有限回合的折扣回报写作：

$$
G_t=\sum_{k=0}^{T-t-1}\gamma^k r_{t+k}
$$

$t$ 是当前步骤，$T$ 是总步数，$r_{t+k}$ 是之后第 $k$ 步的奖励，$\gamma$ 是 0 到 1 之间的折扣系数。假设三步奖励为 $[0,0,1]$，取 $\gamma=0.9$，手算得到 $G_0=0.9^2=0.81$、$G_1=0.9$、$G_2=1$。若有限任务取 $\gamma=1$，三步回报都是 1。折扣越小，远期奖励的权重越低；若查询的好处稍后才出现，过度看重即时奖励可能压低查询动作的学习信号。取值需要跟任务长度、奖励时机和目标一起判断。[Spinning Up 的回报定义](https://spinningup.openai.com/en/latest/spinningup/rl_intro.html#reward-and-return)给出了有限期与折扣回报两种形式。

不过，$G_0=0.81$ 仍不能证明“查询”独自造成了成功。查询正确订单、读懂工具结果、遵守“不取消”的权限，各环节都可能影响末尾分数。把整体结果归因到先前行为，叫**信用分配（credit assignment）**。只给末尾奖励容易定义，却对长轨迹的指导较粗；逐步给分能提供更细信号，但每一步都需要可信的判断标准，错误标准也会奖励看起来规范却无效的过程。订单例子的 0/1 规则可以用于教学，不是已经验证过的生产奖励设计。

## 优势为何要与基线比较

不同观察下，同样的回报含义可能不同：容易的订单查询几乎都成功，复杂订单查询偶尔成功。**优势（advantage）**衡量在某个决策处选这个动作，相对该处通常表现好多少。其定义是：

$$
A(s,a)=Q(s,a)-V(s)
$$

$Q(s,a)$ 是在状态 $s$ 先选动作 $a$、之后遵循当前策略时的预期回报；$V(s)$ 是在 $s$ 遵循当前策略时的预期回报，即比较基线。正优势表示优于基线，负优势表示劣于基线。这里的 $s$ 是完整状态下的形式化定义；订单 Agent 实际只有观察，训练时须用观察或历史去估计所需的价值。两项都是期望值，不能仅凭一条成功轨迹精确算出。[Spinning Up 的优势函数定义](https://spinningup.openai.com/en/latest/spinningup/rl_intro.html#advantage-functions)也采用这一比较。

为了看数值含义，假设在初始观察处，估计的基线回报为 0.5；一次选择“查询”的轨迹得到上面的样本回报 0.81。用“样本回报减估计基线”作**示意性优势估计**，结果是 $0.81-0.5=+0.31$。这不是 $Q-V$ 的精确值，也不证明该动作永远正确；重复采样后估计会变化。如果同一观察下另一次跳过查询的样本回报为 0，按同一基线估计则为 $-0.5$。这两个数只展示更新方向，不代表真实模型测量。

## 学习信号怎样改动策略参数

**策略梯度（policy gradient）**把采样到的动作与其估计优势用于参数更新。最简单的理解是：在相同观察下，正优势样本促使策略提高该动作的概率，负优势样本促使策略降低它的概率。一个示意性训练目标是最大化样本平均的 $\hat A_t\log\pi_\theta(a_t\mid o_t)$；$\hat A_t$ 是从数据估计的优势，$\log\pi_\theta$ 是已采样动作在当前策略下的对数概率。对参数求梯度并沿增大目标的方向走一步，才会改变下次生成时的概率。[Spinning Up 的策略梯度推导](https://spinningup.openai.com/en/latest/spinningup/rl_intro3.html)说明了以采样回报或优势加权对数概率梯度的思路。这个式子用于建立直觉，不包含实际训练所需的完整采样、优化和稳定性处理。

因此，一次成功只提供一个有噪声的样本，不能机械地把整条回答中的每个 token 都判为正确原因。训练要反复采样任务，在受控环境执行、计算反馈与优势、更新策略，再用未见任务独立评估。**在线 RL**通常指训练样本随当前或近期策略的交互产生；它不要求把新权重直接放给生产用户。历史日志也可能用于学习，但要先知道采样策略、能否重建奖励和权限边界。反思或记忆只改变后续输入；[SFT](#/lesson/sft)则提高示范目标 token 的似然，训练信号来自示范。RL 根据策略采样后的反馈改参数，两者可以接续，奖励有漏洞时 RL 同样会学到漏洞。

训练奖励改善后，仍要在未见订单上核对正确率、必要工具调用、权限约束与成本。奖励规则和测试环境若错了，参数更新只会更有效地优化错误目标。后续的 [PPO 论文](https://arxiv.org/abs/1707.06347)讨论怎样限制一次策略更新带来的过强激励；[DeepSeekMath 的 GRPO](https://arxiv.org/abs/2402.03300)讨论同题多次采样时的相对优势。它们是进阶优化方法，不是理解 episode、回报与优势的先修。

<summary>面试怎么回答</summary>

**一分钟回答：Agent 怎样通过强化学习改进选择？**

先把任务写成 episode：策略根据当前观察选择查询或回答等动作，受控环境返回新观察和奖励。回报汇总后续奖励，优势比较某个动作与基线的表现。策略梯度用采样动作及估计优势更新参数，让较好的选择以后更可能出现。末尾成功分数不能精确说明每个中间动作或 token 的贡献，所以要处理信用分配，并在未见任务上验证效果。提示中的反思只改输入；没有训练步骤就没有策略参数更新。

**追问一：reward、return、advantage 有什么区别？**

Reward 是某一步的反馈；return 从当前步汇总未来奖励，可能折扣；advantage 再比较同一决策处的基线。三个量回答的是“这一步得几分”“从这里往后总共如何”“相比通常选择好多少”。样本回报不等于真实期望优势。

**追问二：Agent 看见的聊天历史能直接叫 state 吗？**

通常只能叫 observation 或历史观察的表示。订单数据库的实时状态、权限变化等可能没有呈现在上下文中。只有完整环境状态可见时，观察才足以代表状态；设计工具和评估时要承认这个差别。

**追问三：有了成功日志，是否就完成 RL 训练？**

没有。日志还需要可核验的动作、环境反馈、采样来源和奖励定义；更新模型参数还要实际执行训练。即使奖励上升，也要用未见任务检查事实、权限与成本。单条成功日志尤其无法可靠分配每一步的功劳。

## 练习：判断一次查询的学习信号

仍用 O-18 的教学环境。三步奖励为 $[0,0,1]$，$\gamma=0.9$。初始观察处估计基线为 0.5。请算初始步骤的折扣回报及“样本回报减基线”的示意值，并说明这能否证明每个生成 token 都有贡献。如果测试器只检查答案里是否含“已查询”，Agent 能怎样拿到高分却违背任务目标？

初始回报是 $0+0.9\times0+0.9^2\times1=0.81$，示意性优势估计是 $0.81-0.5=0.31$。它支持提高采样动作概率的方向，却不能精确归因到每个 token；基线和优势也要靠更多样本估计。若只查答复文字，Agent 可以不调用工具而声称“已查询”，甚至沿用旧状态。验收还须核对真实工具调用、订单号、返回状态及写操作权限。

# Transformer：一个 token 怎样读懂前文

假设一个语言模型收到“猫 坐 在”，现在要产生下一个 token。只看末尾的“在”会丢掉前面的主语和动作；只统计出现过哪些词，又无法区分“猫追狗”和“狗追猫”。**已知前缀怎样变成下一 token 的分数？**这是本篇要沿一次计算回答的问题。

Transformer 是处理序列的神经网络架构，许多语言模型采用它的变体。以常见的仅解码器（decoder-only）模型为例，处理一次前缀可以分成四层：

1. token 编号变成向量，并获得位置信息，形成各位置的输入表示。
2. 注意力让每个位置只从允许看到的位置取信息；前馈网络继续变换该位置的特征。残差和归一化把这些计算接成可堆叠的层。
3. 最后一层的末位置表示映射到词表，得到下一 token 的候选分数。
4. 选出一个 token 后把它接到前缀末尾，再计算下一步。已知前缀与逐步续写的计算安排不同。

下面假设“猫”“坐”“在”恰好各占一个 token，方便手算；真实 tokenizer 不保证按字或词这样切分。小向量和权重都是人为构造，**算出的注意力输出不是模型实际会生成的词**。先修只需 [LLM 基础](#/lesson/llm-basics)：token 是模型处理的离散单位，生成任务最终要给词表中的候选 token 分配分数。

## 第一步：编号怎样成为带位置的表示

token 编号本身只是词表索引，例如某个整数指向“猫”。模型通过嵌入表（embedding table）查到一个长度为 d 的向量。这里 d 是隐藏表示的宽度，向量的每一维是可学习数值，通常不能直接命名为“动物”“动作”等固定语义字段。同一个 token 的初始查表结果可以相同，但经过各层后，它在不同上下文中的表示会不同。

若有 T 个 token，把向量按行堆叠，就得到形状 T×d 的矩阵 X。本例 T=3，若取 d=3，就是三行三列：行对应位置，列对应特征。下面省略批次维度；实际程序通常还会有一次处理多少条序列的维度。

还要给计算提供位置信息。只有内容向量和两两比较，无法充分表达绝对或相对位置。原始 Transformer 把位置编码加到 token 向量上；后来的模型也可能在注意力运算中引入位置，不一定都采用相加方式。下文的因果遮罩决定“能看谁”，位置机制则提供距离或次序的信息，职责不同。[Attention Is All You Need，第 3.4—3.5 节](https://arxiv.org/html/1706.03762v7)

原论文的完整架构是编码器—解码器（encoder-decoder），主要用于翻译：编码器表示源句，解码器根据已有目标词和源句表示生成译文。本篇沿 decoder-only 语言模型讲提示与续写，它们位于同一条因果序列，不默认另有一个读取源句的编码器。两者共享基本运算，但不能把原论文整张架构图当成所有现代 LLM 的结构。[Hugging Face：General Transformer architecture](https://huggingface.co/learn/llm-course/chapter1/4)

## 第二步：一个位置怎样取得前文信息

自注意力（self-attention）从同一序列的表示中产生三组向量：查询 Q（query）、键 K（key）和值 V（value）。可以先把 Q 理解为当前位置用于寻找相关信息的表示，K 是各位置用于匹配的表示，V 是最终被混合的信息。这种类比只解释数学角色：它们不是数据库查询，也不是人手指定的关键词。

三组向量由不同的可学习线性投影得到：

$$
Q=XW_Q, \qquad K=XW_K, \qquad V=XW_V
$$

X 的形状是 T×d。若查询和键的宽度为 d_k，则 W_Q、W_K 都是 d×d_k，Q、K 都是 T×d_k。值的宽度可以记为 d_v，W_V 是 d×d_v，V 是 T×d_v。它们来自同一输入，但投影权重不同，因此承担不同职责；训练会调整这些权重，推理时用已有权重计算。

对第 i 个位置，用它的查询向量 q_i 与每个键 k_j 做点积，得到对位置 j 的匹配分数。把结果除以 d_k 的平方根，是缩放点积注意力（scaled dot-product attention）中的缩放步骤，用来控制随着维度增加而可能变大的分数尺度。随后对可见位置的分数做 softmax：先取指数，再除以该行所有指数之和，得到非负且总和为 1 的权重。最后用权重对 V 的各行加权求和。[原论文第 3.2 节](https://arxiv.org/html/1706.03762v7)

整个单头运算写成：

$$
A=\operatorname{softmax}_{\mathrm{row}}\left(\frac{QK^\top}{\sqrt{d_k}}+M\right), \qquad O=AV
$$

K 的转置形状是 d_k×T，所以 Q 乘 K 的转置，产生 T×T 的分数矩阵：第 i 行是位置 i 对所有位置的打分。M 是同形状的遮罩，A 是注意力权重，softmax 按行计算，O 的形状是 T×d_v。这里两次乘法含义不同：Q 与 K 决定怎样分配权重，A 与 V 决定混入什么内容。

## 用三个位置算出注意力结果

让本例的某一层输入 X 是三阶单位矩阵，即三行依次为 [1,0,0]、[0,1,0]、[0,0,1]。这只是方便构造投影结果，并不把真实中文 token 编码规定为单位向量。取一个查询与键宽度 d_k=1、值宽度 d_v=2 的教学注意力头。选择 W_Q=[1,1,1] 的列向量，W_K=[0,ln 2,0] 的列向量，W_V 的三行分别为 [2,0]、[0,2]、[2,2]，便得到：

| 位置 | token 示意 | q | k | v |
| --- | --- | --- | --- | --- |
| 1 | 猫 | 1 | 0 | [2,0] |
| 2 | 坐 | 1 | ln 2 | [0,2] |
| 3 | 在 | 1 | 0 | [2,2] |

ln 2 表示 2 的自然对数，它的指数是 2。观察第 3 个位置：q 为 1，与三个 k 的点积依次为 0、ln 2、0。d_k=1，所以除以平方根不改变分数。第 3 个位置可看见整个已知前缀，此时遮罩 M 的三个值都是 0。对分数取指数得到 1、2、1，总和为 4，权重便是 1/4、1/2、1/4。该位置的注意力输出为：

$$
o_3=\tfrac14[2,0]+\tfrac12[0,2]+\tfrac14[2,2]=[1,1.5]
$$

**[1,1.5] 是混合后的特征向量，不是下一个 token。**第二个位置分到一半权重，只说明这个头在这次计算中怎样分配权重；它不表示“坐”有一半概率正确，也不是事实置信度。

前面算第 3 行时，它已处在前缀末尾，所以三个位置都可见。对其他行需要因果注意力（causal attention）：第 i 个位置只能看自己与之前的位置。用加性遮罩表示，允许位置加 0，禁止位置加负无穷；softmax 后，后者权重为 0。于是第 1 行只看位置 1，第 2 行看位置 1、2，第 3 行看位置 1、2、3。遮罩在 softmax 之前应用，禁止位置不参与归一化。

因此第 2 个位置不能使用第三个 v，即使程序内存里已经放着整个输入。它在 0 和 ln 2 两个分数上归一化，权重为 1/3、2/3，输出是 [2/3,4/3]。第 1 个位置只能得到 [2,0]。这是并行计算与可见范围的区别：三个位置可以一起做矩阵计算，但每行仍受到不同约束。[原论文第 3.2.3 节；Hugging Face 的原始架构说明](https://huggingface.co/learn/llm-course/chapter1/4)

为什么第 3 个位置允许看“在”自己？它的最终输出用来预测第 4 个 token，“在”已属于输入前缀。训练时把预测目标错开一位：第 2 个位置负责预测第 3 个 token。若它能读取第 3 个输入，就会泄露目标。**因果遮罩限制信息可见范围，不要求训练时逐位置运行。**

## 第三步：怎样从一个头走到完整的层

多头注意力（multi-head attention）让不同投影并行产生多组 Q、K、V。各头可能关注不同关系，输出拼接后再经过输出投影，回到隐藏宽度 d。不是给每个头预先指定一个语法职位，也不保证每个头都有清晰可命名的功能。常见配置会把总宽度分给多个头；本篇特意用不常见的小维度方便手算，不是模型配置建议。[原论文第 3.2.2 节](https://arxiv.org/html/1706.03762v7)

经过注意力后，“在”所在的行已有从可见前文混合来的特征。前馈网络（feed-forward network，FFN）继续变换这一行，也同样变换其他行。原论文使用线性变换、ReLU 非线性、再线性变换，输入输出宽度相同，中间宽度更大。相同层的所有位置共用这套权重，但 FFN 分别处理各行，不直接把不同位置混起来。**注意力负责跨位置取信息，FFN 负责逐位置加工已有表示。**

如果只有连续线性变换，中间计算可以合成一次线性变换；加入非线性，才有更丰富的特征组合能力。现代模型可能替换激活或采用其他前馈结构，理解基础层时先把“跨位置混合”和“逐位置变换”分清，不需要同时引入更多训练或稀疏结构。

残差连接（residual connection）把子层输入与子层输出相加，让原表示保留一条直接通路，同时叠加新变换。若输入和输出都是 T×d，它们才能逐元素相加；多头输出投影回 d，也支持这种接口。残差不是把注意力结果直接当最终答案，而是不断更新贯穿层间的隐藏表示。

归一化（normalization）调节每个 token 特征向量的尺度。原论文的 LayerNorm 对一行的特征维计算均值与方差，归一化后再作可学习的缩放和平移；不是把不同样本的统计量都混在一起。原始层采用残差相加后归一化，也就是 Post-LN。现代 decoder-only 模型的归一化类型和摆放位置可能不同，因此不要把下面的原论文写法视为通用实现：

$$
Y=\operatorname{LayerNorm}(X+\operatorname{AttentionBlock}(X))
$$

这里 AttentionBlock 包含多头注意力与输出投影，Y 仍为 T×d；后面再经过 FFN 及其残差、归一化。多个这样的层叠加后，最后一行表示已经经过多轮上下文混合与特征变换。原论文给出了这几项组件的具体组合，本篇省略 dropout、偏置等实现细节。[原论文第 3.1、3.3 节](https://arxiv.org/html/1706.03762v7)

## 第四步：从末位置表示到下一 token

经过全部层之后，模型把末位置的 d 维表示映射为词表大小那么多的分数，称为 logits。假设词表大小为 V_vocab，输出投影矩阵的形状可以写成 d×V_vocab，因此一个位置产生 V_vocab 个候选分数。这与注意力中的 V 矩阵不是同一个对象：V 是被混合的值向量，词表大小只是候选数量。

对 logits 做 softmax，可以得到下一个 token 的分布，再按解码规则选择或采样。选择出的编号被解码为 token，并接到已有序列后面，开始下一步。这里出现的第二次 softmax 在词表候选之间归一化，注意力 softmax 则在可见位置之间归一化；两者公式形式相似，回答的问题不同。[原论文第 3.4 节](https://arxiv.org/html/1706.03762v7)

以“猫 坐 在”为前缀，模型在末位置算出 logits，选出第 4 个 token，随后把它接到前缀后，再预测第 5 个。**这两段计算的输入可知程度不同。**提示处理阶段通常称为预填充（prefill）：三个提示 token 已知，可以在各层按因果遮罩并行处理，末位置 logits 用来产生第一个新 token。后续逐 token 生成阶段称为 decode：刚生成的新 token 进入各层，取得下一步分布。第 5 个 token 还不存在时，普通自回归生成不能提前并行算完后续所有位置。

常见推理实现会保存每层已处理位置的 K、V，作为 KV cache。新 token 的 Q 可以与缓存中的旧 K 以及新 K 匹配，再加权对应 V，不必重新计算所有旧位置的 K、V。在标准因果结构中，追加未来 token 不改变先前位置可见的前缀，这是复用的基础。缓存按层保存，随着上下文增长会占空间；它不是把旧文字变成永久知识，也不改变模型权重。[Hugging Face：Caching](https://huggingface.co/docs/transformers/en/cache_explanation)

到这里，一次续写的链路才完整：token 编号成为带位置的表示，Q/K 决定从哪些可见位置取信息，权重混合 V，多头与 FFN 更新特征，残差和归一化组织层间传递，词表投影给出下一 token 分数。手算例子验证了其中一个头怎样混合信息，没有声称用三个小向量就复现了语言理解。

<summary>面试怎么回答</summary>

**一分钟回答：** Transformer 把 token 转成向量并加入位置信息，通过自注意力使各位置交换信息。Q 与 K 的缩放点积经遮罩和按行 softmax 得到权重，再加权 V。decoder-only 模型用因果遮罩限制未来信息。多个头的结果拼接投影，经过逐位置 FFN、残差和归一化，层层更新隐藏表示，最后映射为词表 logits 来预测下一个 token。Prefill 并行处理已知提示，decode 逐 token 继续生成，KV cache 复用每层前缀的 K/V。原论文是 encoder-decoder，不能与所有现代 LLM 结构直接画等号。

**追问一：Q、K、V 来自同一个 X，为什么要分三个投影？** 匹配和传递信息是不同任务。Q/K 决定注意力分数，V 提供被汇总的内容，不同可学习投影让这两部分有各自表达空间。它们不是三份完全独立输入，也不是手写规则字段。

**追问二：既然训练能并行，为什么生成还要逐个 token？** 训练时目标序列已知，可以把输入错开一位，并用因果遮罩并行计算所有位置的预测；生成时下一个输入 token 取决于刚产生的结果，尚未确定。并行算已知位置与提前知道未来 token 是两回事，缓存只能减少重复计算，不能取消这种普通自回归依赖。

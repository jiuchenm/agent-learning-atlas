# 文档解析：PDF 里的字为何不能直接入库

假设用户问：“外部讲师能把培训设备借走 5 天吗？”知识库检索到了制度里的“外部讲师、3 天、可续借 1 次”，于是助手回答“可以，先借 3 天再续借”。但原 PDF 的表格写的是外部讲师不得续借，那一次续借属于上一行的内部员工；表格下方还写着培训设备统一不得续借。检索命中了正确文档，答案依然错了，因为材料进入索引之前，行列关系和例外已经被解析坏了。

文档解析（document parsing）负责把页面上的文字与组织关系转为程序能够使用的内容。它不只识别“有哪些字”，还要恢复阅读顺序、标题层级、表格关系和来源位置。以下制度、页面及输出均为教学构造，没有真实客户文档，也没有运行 OCR 服务。目标是理解解析如何影响 [RAG](#/lesson/rag-basics) 的证据质量；如何把内容切成检索片段，留到 [Chunking](#/lesson/chunking)。

## PDF 页面上的信息不只是一串文字

有文本层的数字 PDF 通常可以提取字符，但这些字符的存储或绘制顺序，不一定就是人阅读的顺序。版面中的两栏、表格、侧边说明和页脚，可能在提取后混到一起。扫描 PDF 则主要保存页面图像，需要光学字符识别（Optical Character Recognition，OCR）从像素中识别文字。有些文件同时包含原生文字、扫描页或已有 OCR 层，所以处理单位常常需要细到页面，而不是看到扩展名就认定整份文件都能直接抽取。

OCR 解决字符识别，版面分析（layout analysis）进一步判断哪些文字属于一段、一个标题、一张表或一条脚注。Azure Document Intelligence 的 Layout 文档把几何元素与逻辑角色分开：表格、图像和文字区域提供位置结构，标题、节标题、页脚等角色提供组织线索。输出这些结构只是解析能力的说明，不是对任意文档都完全准确的保证。[Microsoft Learn：Layout v4.0，核验于 2026-09-28](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/layout?view=doc-intel-4.0.0)

多栏文档特别容易暴露这种区别。左栏讲借用条件，右栏讲管理员入库步骤，按整页从左到右逐行拼接，可能把两个流程交替排列。正确做法要先识别区域，再决定区域之间和区域内部的阅读顺序。即使字符一个没认错，错误顺序也会产生原文没有的句子。官方响应说明中明确指出，阅读顺序可能跨行或跨栏组织，而存在歧义时会采用一般顺序；该版本不支持跨页阅读顺序，因此跨页衔接仍需检查。[Microsoft Learn：Analyze document response](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/concept/analyze-document-response?view=doc-intel-4.0.0)

## 把一页借用制度恢复成可追溯的数据

假设源文件是《培训设备借用规定》第 4 版，9 月 1 日生效。PDF 有一页封面，所以文件中的第 3 页，页脚印的是“第 2 页”。这一页左栏标题为“普通设备借期”，右栏是“管理员登记步骤”。左栏有如下表格，表下注释也属于制度的一部分：

| 借用人 | 首次借期上限 | 续借次数上限 |
| --- | --- | --- |
| 内部员工 | 7 天 | 1 次 |
| 外部讲师 | 3 天 | 0 次 |

表下注释：“培训设备不适用续借。续借次数为 0 表示不得续借。”右栏另写：“管理员每周检查设备记录，借用登记需填写预计归还日期。”这个行政步骤没有延长任何人的借期。

一个错误的纯文本抽取结果可能是下面这样。它故意展示行列关系丢失，并不是某个真实解析器的实测输出：


```text
普通设备借期
内部员工 外部讲师
7 天 3 天
续借 1 次 0 次
管理员每周检查设备记录
借用登记需填写预计归还日期

```

表头与单元格关系消失，脚注也漏了。后续系统即使同时取到“外部讲师”“3 天”和“1 次”，仍不知道哪个数字属于哪一行。更换更强的生成模型可能让它猜对，但不能恢复被删除的脚注，也不能保证把猜测和原文事实分开。

较好的解析结果先保留原始单元格、行列位置、表头和表下注释。转换成可供检索的表达时，再把表头带入每条记录，例如“外部讲师：首次借期上限 3 天；续借次数上限 0 次”。同时保留“培训设备不得续借”的原文及它与这张表的关联，而不是认为正文文字越少越干净。

下面是该页经过检查后的教学用中间记录，只展示外部讲师这一行。字段由本例应用定义，不是 Azure API 返回契约；位置也是假设坐标。normalizedRect 表示相对于页面宽、高归一化的左、上、右、下边界，因此四个值都在 0 到 1 之间。


```json
{
  "source": {
    "documentId": "training-equipment-policy",
    "version": "4",
    "effectiveFrom": "2026-09-01",
    "accessPolicyRef": "policy-training-equipment-readers"
  },
  "location": {
    "pdfPageNumber": 3,
    "printedPageLabel": "2",
    "section": "普通设备借期",
    "tableId": "table-1",
    "normalizedRect": [0.08, 0.28, 0.48, 0.40]
  },
  "row": {
    "borrower": "外部讲师",
    "initialDaysMaximum": 3,
    "renewalCountMaximum": 0
  },
  "relatedNote": "培训设备不适用续借。续借次数为 0 表示不得续借。",
  "reviewStatus": "checked_against_source"
}

```

恢复后的材料支持明确的答案：“不能。外部讲师首次借期最多 3 天且不得续借，培训设备也不适用续借。依据第 4 版文件第 3 个 PDF 页面，印刷页码为第 2 页。”如果用户要的是 5 天，就不能把内部员工的 1 次续借拿来拼出许可。这里的正确性来自行与表头的对应、注释保留和来源核对，而不是模型猜测出的业务常识。

这个结果还应能打开原文对应位置。documentId 加版本确定是哪份文件，PDF 页序号用于定位，印刷页码用于与读者看到的页脚对齐，区域坐标用于高亮证据。只有一个“第 2 页”字段，容易把封面造成的页码差错带到引用里。表格跨页时，一个逻辑对象还可能关联多个页面区域，不能强行只保留一个页码。

## 表格结构、字符位置和元数据各有用途

表格解析需要保存行列索引、跨行跨列范围及表头角色。合并单元格尤其值得检查：一格“不得续借”如果覆盖两行，扁平化后必须让两行都关联它；如果只作用于一行，又不能扩散成整张表的规则。空单元格也不能随便补成上一行的值，它可能表示不适用、未填写或沿用上方合并格，需要根据原页结构区分。

跨页表格还可能在新页重复表头。重复标题不是一条新的业务记录，页末尚未结束的一行也不一定在下一页有相同高度。连接前应核对列结构、表名、连续内容和脚注。Azure Layout 文档介绍了单元格索引、跨行跨列和位置输出，同时指出 v4.0 的表格边界区域只覆盖表格主体，不包括相关标题与脚注。由此可见，只截取表格主体再丢弃周围内容，可能正好丢掉决定含义的条件。[Microsoft Learn：Layout 的 Tables](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/layout?view=doc-intel-4.0.0)

除了页面坐标，解析结果常保存字符范围（span）：某个段落在统一文本中的起始偏移和长度。坐标回答“原页哪里”，span 回答“解析文本哪里”，用途不同。若清理空格、改换行或重新拼接内容，偏移可能失效，因此应保留原始文本与规范化文本的对应关系，或重新计算偏移。中文、emoji 等字符还会涉及字符计数单位，不能默认所有语言运行时的字符串长度都等价。官方响应说明区分了字符范围和视觉位置，也说明图像、PDF 的位置单位需要读取实际返回值。[Microsoft Learn：Spans 与 Bounding Region](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/concept/analyze-document-response?view=doc-intel-4.0.0)

元数据（metadata）还要记录解析本身：采用什么解析器或模型版本、何时处理、原文件版本或校验值、哪些页面走了 OCR、哪些关键区域需要复核。以后更换解析器，才能比较同一份输入的差异，而不是把源文件更新造成的变化误判成算法改善。普通空白和页眉可以规范化处理，但数字、单位、否定词、比较符号与条款编号应有明确保留规则。

源文件版本和授权范围不能只靠 OCR 猜。文档封面可能写了“第 4 版”，但哪个版本当前有效，还要结合来源系统中的发布状态与生效信息。哪些用户能读这份文件，则应从知识源的权限信息取得并关联到派生记录；印着“内部使用”不等于机器已经知道具体允许哪些用户访问。后续检索必须执行相应权限判断，解析出文字并不会赋予任何人额外访问权。若使用外部解析服务，是否允许把该文档交给服务处理，也应在提交前确定。

## 解析错误怎样进入最终答案

不同错误会沿着不同路径传播。OCR 把“7 天”认成“1 天”，会改变事实值；把“不得”漏成“得”，会反转条件；把外部讲师与上一行数字相连，会制造不存在的关系；删掉版本与权限，则会让旧规则或不该访问的材料进入候选集合。它们发生在检索之前，最终回答仍可能语言通顺、引用齐全。

这也是为什么只观察最终答案的准确率不够。文档解析至少要分开检查字符、阅读顺序、表格结构、条件关联和位置可回溯性。对本例，验收样本应包含三列关系、两种借用人、培训设备脚注、封面页码偏移，以及双栏不会交叉拼接。更进一步，可以提出“外部讲师能否借 5 天”“内部员工能否续借培训设备”这类问题，检查解析结果是否保留足够证据，但不要用生成模型猜对一次来代替原页核对。

置信度可以帮助选择复核区域，不能直接当作最终答案正确的概率。字符识别得很有把握，不表示它被放进了正确的表格行。对金额、天数、零次、否定词等决定性内容，应根据错误后果安排抽检或人工核对；模糊到无法确认时，保留未知并回到更清晰的原件，不让模型自动补出一个合理数值。本例中的 checked_against_source 只是教学流程设定，现实系统必须有相应检查记录才可以这样标记。

解析的交付物应同时保留便于机器处理的结构、便于模型阅读的正文，以及回到原文件的定位。原文、解析结果和规范化内容各有职责。完成这一步以后，才进入分块阶段；分得再巧，也无法保证找回前面已经丢失的“不适用续借”。

**一分钟回答：** 文档解析不只提取字符，还要恢复阅读顺序、标题、表格和脚注关系。数字 PDF 可能有文本层，扫描件需要 OCR，混合文档要按页处理。输出应保留正文及结构，再带上源文件版本、页码、坐标或字符范围和权限关联。否则把一个数字接错行、漏掉否定或例外，后续 RAG 即使命中正确文件也会答错。验收既看字符，也看表头对应、条件关联和能否回到原页；无法确认的关键内容需要复核，不能靠模型猜。

**追问一：为什么不把 PDF 全转成 Markdown 就够了？** Markdown 可以是阅读和检索表示，但转换时仍可能丢掉合并单元格、脚注、双栏顺序和位置。需要保留结构与来源映射。比如外部讲师的“0 次”一旦丢失，漂亮的 Markdown 不会自动修复它。

**追问二：OCR 置信度高，为什么还要检查表格？** 字符置信度与关系正确性是不同问题。“1 次”和“0 次”都可能识别正确，却被连到错误借用人。应检查单元格和表头映射、跨行范围、脚注关联，再核对影响决策的数值和否定条件。
